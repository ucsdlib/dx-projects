# primo-mcp

> **Status: exploration and testing only.** Not production-ready and not for patron use.

## About this project

This is a personal learning project for building a read-only MCP (Model Context Protocol) server that searches a library catalogue (Ex Libris Primo) from an AI assistant.

It follows a step-by-step guide generated by Claude (Anthropic), based on my prompts and Claude's deep research tool. Parts of the code and guide have not been fully verified, so expect rough edges.

## Tools

All three tools are read-only (`read_only_hint=True`). Every tool returns structured data, and a failure comes back as a tool error with a plain-language message.

### `search_catalogue`

Searches the library catalogue (Primo) and returns brief records with permalinks.

| Argument | Notes |
| --- | --- |
| `query` | Required. String, 2–200 characters, e.g. `"climate adaptation"`. Searched as a "contains" match across all fields. |
| `limit` | Optional. Integer, 1–10, default 5. Also capped by the `MAX_RESULTS` setting. |

Returns `query`, `total_found`, and `records`. Each record has `title`, `creators` (up to 5), `date`, `resource_type`, `record_id` and `link`. Results also carry a `notice` that reminds the AI the text is data, not instructions.

### `search_databases`

Searches the library's A-Z list of research databases by name, alternate name, subject, type or description. It answers from a local SQLite copy of the list and does not call LibGuides at query time.

| Argument | Notes |
| --- | --- |
| `query` | Required. String, 2–100 characters, e.g. `"nursing"` or `"JSTOR"`. |
| `limit` | Optional. Integer, 1–10, default 5. |

Returns `query`, `returned`, `last_synced` and `databases`, plus a `notice`. If the list has never been loaded, the tool returns an error asking the server owner to run the sync.

### `get_database`

Gets one A-Z database record by its id, as returned by `search_databases`.

| Argument | Notes |
| --- | --- |
| `database_id` | Required. Integer, 1 or higher. |

Returns `database_id`, `name`, `description`, `url`, `proxied`, `vendor`, `alt_names`, `subjects` and `types`. An unknown id returns the error "No database with that id."

## Privacy and safety

This server is read-only, and it is built so that the AI sees as little as possible. The checks below are covered by the tests in `library_mcp/tests/`.

**Secrets**

- **Keys stay in `.env`.** The Primo API key and the LibGuides client ID and secret are read from environment variables. `.env` is git-ignored, and only `.env.example` (with placeholder values) is committed.
- **Keys are never shown to the AI.** The Primo key is sent in the `Authorization` header, not the URL, so it does not appear in logs or query strings. Error messages name the setting to check (for example `PRIMO_API_KEY`) but never print its value.
- **Tests never touch real systems.** The test fixtures replace every setting with fake values and use mock HTTP transports, so no test can reach live Primo or LibGuides, or read your real `.env`.
- **Logs go to stderr, and the API key is never logged.** The server's own log line records only the length of the query and the number of results. The HTTP library's request logging is turned down to WARNING, so the request URL (which contains the search words) is not logged. The API key travels in a header and is never logged. Logs stay on the local machine, in the Claude Desktop MCP log. Claude Desktop keeps its own `mcp.log` as well, which this server doesn't control and which may record tool arguments.

**Only the fields that are needed**

- **Allow-list mapping.** Records are built by reading only the named fields, and everything else in the API reply is ignored. A Primo record yields a title, up to 5 creators, a date, a resource type, an id and a link. A database record yields its id, name, description, URL, proxy flag, vendor, alternate names, subjects and types.
- **Hidden records are dropped.** A-Z entries marked hidden never reach the local copy, and records without a numeric id, a name or an `https://` URL are skipped.
- **Private notes stay out.** Test data that includes internal fields (such as passwords or "do not share" notes) is checked to confirm none of it appears in the output.
- **Email addresses are removed.** Database text has HTML tags stripped and email addresses replaced with `[email removed]`.
- **Every field is trimmed.** Control characters are removed and whitespace is collapsed. Catalogue fields are capped at 300 characters, database descriptions at 500, and lists at 5–10 items.

**Prompt injection**

- **Record text is treated as untrusted.** The server instructions say record text is data. Every result also carries a `notice` telling the AI to treat the text as data, not instructions.
- **Injection text is not passed on.** A test record containing "IGNORE ALL PREVIOUS INSTRUCTIONS" is checked to confirm the phrase does not appear in the returned record. A matching test for A-Z database descriptions is drafted in `test_safety.py` but is currently commented out.
- **Tool inputs are validated.** Argument lengths and ranges are enforced before any code runs. Search words also have commas, semicolons and control characters removed, so a query can't change the structure of Primo's `q=field,precision,value` parameter.
- **Read-only by design.** No tool writes, edits or deletes anything in Primo or LibGuides.

**Respecting API limits**

- **Caching.** Repeat catalogue searches (ignoring case and extra spaces) are served from memory for 5 minutes. The cache holds at most 256 entries, removes expired ones, and drops the oldest first.
- **No duplicate calls.** If several identical searches arrive at once, only one request goes to Primo and all of them share the result. Failures are shared with every waiting caller and are never cached, so the next search tries again.
- **Quota awareness.** If Primo reports that 5 or fewer API calls remain for the day, the server pauses searches. A daily-limit response gives a message that the allowance resets at midnight GMT, and a rate-limit response asks the user to wait and retry.
- **Timeouts.** Primo requests time out after 20 seconds and LibGuides requests after 30.
- **Database search uses a local copy.** Database questions never hit LibGuides. A separate sync job refreshes the list, and the LibGuides token is reused until shortly before it expires.
- **Safe syncing.** A sync that returns no usable records, or fewer than half the existing records, is rejected and the previous list is kept.
- **Friendly errors.** Bad credentials, wrong view/tab/scope settings, timeouts and server errors each map to a short message, without the raw API response.

## Getting started

If you'd like to try this out or build on it, here's how to run it locally.

### Requirements

- Python 3.12 or newer
- Node.js (only needed for `mcp dev`, which launches the MCP Inspector through `npx`)

### Check for Python

Before installing, check whether Python 3.12+ is already on your machine:

```bash
python3 --version        # Windows: py --version
```

If you see `Python 3.12.x` or higher, skip ahead to [Install](#install). If the command isn't found, or the version is older than 3.12, install Python using one of the options below.

**Option 1: python.org installer (works on macOS and Windows)**

Download the latest stable release from [python.org/downloads](https://www.python.org/downloads/).

- **macOS:** run the `.pkg` installer.
- **Windows:** use the Python install manager (listed first on the download page), or the standalone `.exe` installer. If you use the standalone installer, tick **"Add python.exe to PATH"**.

**Option 2: uv (macOS, Windows, and Linux)**

[Install uv](https://docs.astral.sh/uv/getting-started/installation/), then run:

```bash
uv python install
```

This installs the latest Python. uv can also manage the environment for this project; see [Using uv](#using-uv-optional) below.

**Linux:** python.org only offers source code for Linux, so use your distribution's package manager (for example `sudo apt install python3 python3-venv` on Debian/Ubuntu) or Option 2. Make sure the version it installs is 3.12 or newer.

After installing, open a new terminal window and re-run the version check.

### Install

From the project folder:

```bash
# Create and activate a virtual environment
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# Install the project and its dependencies (reads pyproject.toml)
pip install -e .
```

The `-e` flag installs in editable mode, so changes to `server.py` take effect without reinstalling.

### Run

```bash
# Open the MCP Inspector in your browser to try the search_books tool
mcp dev server.py

# Or run the server directly (it waits for an MCP client over stdio)
python server.py
```

`mcp dev` is the easier way to check that the tool works. The server currently searches a small list of made-up books, not a live catalogue.

### Using uv (optional)

If you already use [uv](https://docs.astral.sh/uv/), you can skip the steps above. `uv sync` creates the environment from the pinned versions in `uv.lock`, and `uv run mcp dev server.py` starts the Inspector. pip users can ignore `uv.lock`.

## What's next

This only works in a local development environment for now. In this case it runs on one machine and is used with Claude. Nothing is hosted, and it isn't available to patrons or other AI systems.

Collaboration with library peers is underway to host this server and make it available to more agentic systems. A more technical README (configuration, architecture, deployment) will be added once the project nears a shareable proof of concept.
