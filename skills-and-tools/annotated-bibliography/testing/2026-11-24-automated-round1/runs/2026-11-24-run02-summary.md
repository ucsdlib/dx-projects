## Cross-Scenario Patterns

### Recurring Issues

- **No effort/expectation signaling (3/3 deep or near-deep turns).** Every session announced *what* it was about to do (scope, plan, tier) but none stated rough time cost before starting. Deep runs took ~5-12 minutes. This is the confirmed baseline failure for the phase 3 right-sizing requirement.
- **Manifest schema drift (3/3 runs).** Three runs, three shapes: `breadth_tier` as descriptive string (S01), nested object (S02), flat string with phase-state overwrite (S03); query records inconsistently bundled (S01) or purpose-less (S03). The PRD's proposed `landscape_tier` / `deep_work_tier` / `effort_mode` fields plus additive stage logs would fix all three.
- **Clarification discipline held (3/3).** All sessions proceeded without clarifying questions when prompts carried enough scope — the "clarify once, only when material" rule works in practice.

### What Worked

- The full landscape → selection → deep-work arc is functional end-to-end for the first time in live multi-turn testing.
- Landscape carry-forward, reuse-first refinement, documented pruning, Crossref verification, DOI-first links, and abstract-level honesty all held under load.
- Turn 3 probes in all scenarios were answered from actual run state with honest boundary language — strong evidence for the guided-inquiry direction.

## Top Blockers and High-Impact Issues

1. **[High] Effort/expectation signaling absent before deep work.** Scope is announced; time cost never is. Root cause: no requirement or template element exists in the current SKILL.md or response templates. Direct evidence in S02 and S03 deep-work turns.
2. **[Moderate] Tier-effort semantics undefined.** S02 reached "Comprehensive" with zero new searches (curation-only, defensible under reuse-first but never explained to the user); S03 ran 15 queries for the same tier. "Comprehensive" currently means whatever the session decides.
