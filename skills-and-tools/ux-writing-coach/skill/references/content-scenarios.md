# Content Scenarios and Reference Routing

Use this map to choose the smallest relevant set of references. It covers the UX writing scenarios Library staff are likely to bring to the coach. Start with the scenario row, then read only the listed references.

**Universal rule:** For any task that drafts, rewrites, reviews, evaluates, or otherwise changes copy, also read [voice-and-messaging.md](voice-and-messaging.md). Do not treat voice as optional context; apply it together with the scenario-specific guidance below.

**Molecule rule:** When the task maps to a reusable service-copy pattern—such as a service overview, service-offering card, eligibility and access section, form, status message, or contact and support section—read the relevant molecule in [content-strategy-elements.md](content-strategy-elements.md) before drafting or restructuring.

**Intake rule:** For service, collection, space, or expertise requests, classify input and decide whether to show a working plan by reading [working-plan.md](working-plan.md). If the request is clear and complete, draft directly.

**Response-template rule:** Read [response-templates.md](response-templates.md) to select the response shape. For structured content, use the plan-only template and stop for review before drafting unless all Plan Gate inputs are supplied.

## Scenario-Specific Checks

### Service Pages and Long-Form Help

- State the user’s task in the first sentence or heading.
- Lead with the action or benefit; move internal process later.
- Use meaningful headings and one idea per paragraph.
- Define Library terms in context when needed.
- Verify service names, locations, hours, and policies with the user.

### Policies, Access, and Restrictions

- Lead with what the user can do.
- State eligibility, limits, and required credentials after the opening path.
- Preserve the boundary and explain why it exists only when useful.
- Avoid vague phrases such as “access restricted” when the actual condition is known.

### Forms and Interface Copy

- Label controls by the result, not the mechanism.
- Use sentence case for labels and buttons unless the interface standard differs.
- Keep placeholder text supplementary; do not replace a visible label with placeholder text.
- Make empty states, errors, and success messages actionable.

### Errors, Alerts, and Outages

- Say what happened in plain language.
- Say what the user can do next.
- Name the support path only if it is accurate.
- Avoid blame, jargon, and unnecessary apology.

### Wayfinding and Spaces

- Use exact building, floor, direction, and room names.
- Add floor and direction when the room name alone is insufficient.
- Do not use “wings” or “Commons” for Geisel locations.
- For WongAvery, use “WongAvery” or “WongAvery Library” as the location.

### Events and Promotions

- Include the user’s action, date, time, location, audience, and any registration step.
- Use the event’s exact name and capitalization.
- Include a time zone only when the audience spans zones.
- Use brand warmth without exaggeration or vague hype.

### Catalog, Databases, and Research Guides

- Use exact system names: UC Library Search, UC San Diego Library catalog, Get it at UC.
- Explain specialized terms in the user’s task context.
- Make link text describe the database, guide, or action.
- Distinguish Library Guides from a specific guide title.

### Collections and Archives

- Use the exact collection name and approved short form.
- Preserve ampersands when part of the formal name.
- Do not call the Library’s general circulating materials a “collection” unless the source does.
- For Special Collections & Archives, use the exact program name and facility distinction.

### People and Titles

- Verify spelling, title, degree, and current role.
- Capitalize formal titles only before a name.
- Use singular “they” for unspecified or unknown gender.
- Include class years only when relevant and confirmed.

### Inclusive Language

- Include identity only when relevant.
- Confirm preferred terminology when possible.
- Avoid assumptions about ability, gender, citizenship, family status, race, ethnicity, or background.
- Refer legal or policy questions to the appropriate campus office or expert.
