# UX Writing Principles and Output Patterns

Use this reference to choose copy size, restructure content, handle jargon, revise microcopy, and evaluate audience fit.

Cite sources with the compact labels and canonical URLs in [source-citations.md](source-citations.md).

## Copy Sizes

| Size | Definition | Primary use |
| --- | --- | --- |
| Long-form | 3 or more paragraphs forming a coherent unit | Policy pages, service documentation, longer how-to guides, “About” copy, complex processes, and topics where users need depth. |
| Short-form | 1–3 paragraphs communicating a small number of main ideas | Service descriptions, help articles, feature introductions, onboarding, and key messages that should be found quickly. |
| Microcopy | Fewer than 3 sentences | Labels, buttons, links, errors, tooltips, navigation, placeholder text, empty states, cards, and other interface guidance. |

Long copy still needs meaningful headings, summaries, and scannable units. Microcopy should be judged by its primary purpose, not only by where it appears.

## Write for Scanning

Users scan web copy rather than read every word. Favor:

- The inverted pyramid: lead with the conclusion or action, then supporting detail, then background.
- One idea per paragraph.
- Meaningful headings that describe content, such as “Request a book from another library,” rather than vague labels such as “Getting what you need.”
- Short sentences and paragraphs.
- Bulleted lists for parallel items.
- Front-loaded keywords and user tasks.
- Objective language rather than hype.

As a rule of thumb, aim for about half the word count of conventional writing when that reduction does not sacrifice necessary meaning. If a longer explanation is needed, trim elsewhere or improve structure rather than removing essential content.

## User-Centered Transformation

The default revision intensity is a user-centered transformation, not light polish. Identify the reader’s task first, then lead with the action or benefit. Place rules, caveats, and background after the opening path.

| Organization-centered pattern | User-centered approach |
| --- | --- |
| Starts with internal process, unit structure, or classification | Lead with what the user needs to accomplish and where to start. |
| Opens with eligibility or restrictions | Lead with the possible action, then state eligibility and any necessary limit. |
| Explains why the Library cannot fulfill a request | Explain available paths, then the reason for the boundary if needed. |
| Uses internal vocabulary or a policy label | Translate it into the user’s action; introduce the exact term only when necessary. |
| States policy as a prohibition | State the allowed action, condition, deadline, or alternative first, while preserving the limit. |

Do not hide material limits, imply eligibility that does not exist, or invent alternatives. For service-critical copy, make clarity and reassurance the priority.

## Microcopy: Inform, Influence, Interact

Name the primary goal before revising:

- **Inform:** deliver information or guidance, as in tooltips, status messages, error explanations, and placeholder instructions.
- **Influence:** encourage a specific action, as in calls to action, promotional copy, and taglines.
- **Interact:** support interface use, as in button labels, navigation, breadcrumbs, and form-field labels.

Common revisions:

- Replace generic “Submit” with what actually happens, such as “Send request” or “Request this item.”
- Make errors actionable: state what happened, why it may have occurred, and what the user can do next.
- Make link text specific: “See borrowing policies,” not “Click here for more information.”
- Make “Learn more” concrete: “Learn more about course reserves.”
- Turn restrictions into doors when possible: “Sign in with your UC San Diego credentials to access this resource” is clearer than “Access restricted.”

For microcopy, offer 2–3 distinct options, each with a one-line rationale. Label tradeoffs such as clearer, warmer, shorter, more authoritative, or more specific.

## Brevity Techniques

Cut without changing meaning:

- Focus on essentials for the user. If a phrase does not help the reader understand or act, cut it.
- Remove filler such as “It is important to remember that.”
- Remove unnecessary intensifiers such as “very,” “extremely,” “quite,” and “really.”
- Remove redundancy within and across sentences.
- Use one idea per sentence where possible.
- Prefer active constructions when the actor matters.
- Prefer adjectives or verbs over long noun phrases.
- Rearrange a sentence when reordering reveals a shorter, clearer form.

Brevity should not outweigh clarity. When a longer explanation is necessary, keep it and tighten surrounding copy.

## Jargon Handling

Before using a specialized term, ask:

1. Will most intended readers know it?
2. How important is this exact term to the task?

Then choose:

- If most readers know the term, use it without explanation.
- If most readers do not know it and the exact term is important, lead with plain language: “borrow books from other libraries (interlibrary loan).”
- If most readers know the term but some may not, lead with the term: “interlibrary loan (borrow books from other libraries).”
- If the term is not important, replace it with plain language.
- If a textbook definition is insufficient, explain what the term means in the user’s context.

Write out acronyms on first reference when needed. Consider avoiding acronyms entirely in public copy. Useful patterns:

| Term | Plain-language introduction |
| --- | --- |
| Interlibrary loan | “borrow books from other libraries (interlibrary loan)” |
| Peer-reviewed | “articles reviewed by other experts in the field” |
| Citation management | “tools to organize your sources” |
| Metadata | “record details like title, author and subject” |
| Federated search | Avoid; describe the search behavior instead |

## Audience Evaluation

Determine relevant audiences from the content and task. Do not force a fixed number. Potential lenses include first-time undergraduates, first-generation students, transfer students, graduate and professional students, faculty and researchers, Library and campus staff, alumni and donors, parents and families, community borrowers, members of the public, visitors, users with disabilities, international users, and non-native English speakers.

For each relevant lens, assess:

- Task: Can this user recognize what to do next?
- Vocabulary: Are terms clear or appropriately defined?
- Scannability: Can the user find the relevant section quickly?
- Specificity: Are next steps, locations, times, costs, and limits clear?
- Inclusion: Does the copy avoid unnecessary assumptions or stigmatizing framing?
- Tone: Is it human, credible, useful, and appropriate to the situation?
- Accessibility-adjacent issues: Are headings meaningful, link text descriptive, and interface labels understandable without surrounding context?

Use the user with the least prior knowledge or greatest need as the clarity standard. Label audience observations as hypotheses when they are not evidence-based. State the hypothesis in one short line, such as “Hypothesis: first-time students may not know what a known-item search is.” Recommend user testing when terminology, emotional resonance, or audience fit is uncertain.

## Output Patterns

### Drafting

For each alternative:

- Show the option.
- Give one concise reason it works.
- Name the tone, audience, or tradeoff when useful.
- Invite iteration.

For short-form copy, offer two versions or a recommended revision plus a bolder alternative. Explain what changes in tone, length, emphasis, specificity, or audience fit.

For long-form copy, propose structure and cuts before rewriting. Offer alternative treatments of the highest-impact section, or identify the one or two places where a different approach would materially change emphasis, length, or audience fit. Rewrite the full draft only when the user asks for it.

### Feedback

Use:

1. **What works**
2. **Top opportunities**
3. **Suggested revisions**
4. **Why**
5. **Next step**

For line edits, this table is acceptable:

| Original | Suggested revision | Why |
| --- | --- | --- |

### Evaluation

For an audience review, this table is often useful:

| Audience lens | What works | Likely questions or barriers | Suggested variation |
| --- | --- | --- | --- |

Separate high-confidence style or UX findings from audience hypotheses and questions needing user research. End with concrete next steps, such as human expert review, policy confirmation, accessibility review, or user testing.
