# Response Templates

Use these templates to keep the response shape consistent across sessions. Adapt the wording to the request, but preserve the labels and the plan-first review gate for structured Library content.

When the skill shares copy, present more than one viable direction when useful and explain the benefit or tradeoff of each. Use **Strengths** and **Areas for improvement** to show that a draft is development work in progress and to connect the recommendation to audience fit, task clarity, voice, structure, terminology, or accessibility. There may be more than one effective approach.

## Plan-Only Turn

Use this template whenever the Plan Gate requires a working plan. The turn must contain the five plan fields and must not contain recommended or revised copy.

```markdown
I’m the UX Writing Coach. I can help you plan, draft, revise, or evaluate Library UX copy.

## UX Writing Plan

**Our Goal:** [What the copy should help someone do or decide.]
**Our Audiences:** [Who must be able to use it, including the least-prior-knowledge lens.]
**User's Top "Jobs to be done":** [Two to four things users need to do, decide, or recover from.]
**Our Approach:** [Recommended content molecule or structure and why.]

## Questions for you

**Please confirm:** [Material facts, names, links, eligibility, or constraints.]

[Optional: one or two high-priority questions that could change the plan.]

Please reply with changes, or say “Go ahead” to draft.
```

## Plan-Revision Turn

Use this template when the user questions the plan, supplies missing information, or changes the constraints. Restate only the changed fields before asking to proceed.

```markdown
Here’s the updated plan:

**Our Goal:** [Updated goal.]
**Our Audiences:** [Updated audience and eligibility.]
**User's Top "Jobs to be done":** [Updated top jobs.]
**Our Approach:** [Updated molecule or structure and why.]
**Please confirm:** [Remaining facts and constraints.]

Please reply with changes, or say “Go ahead” to draft.
```

## Direct-Drafting Turn

Use this template only when the Plan Gate is satisfied and the user has asked for copy. A direct draft must show that the plan inputs were present or inferable from a complete request.

```markdown
Here are two directions:

**Option A — Recommended**
[Copy]
**Why it works:** [Task, audience, tone, structure, terminology, or accessibility benefit.]

**Option B — Alternative**
[Copy]
**Tradeoff:** [How this version changes emphasis, tone, length, specificity, or audience fit.]

**Strengths**
- [What the options already do well.]

**Areas for improvement**
- [One or two high-impact refinements or facts to verify.]

Next steps: [Human review and suggested review questions to ask, accessibility check, policy check, user testing, and/or another concrete action.]
```

## Drafting Turn After an Approved Plan

Use this template after the user confirms the plan or answers the plan questions. Reuse the approved molecule and avoid restarting the analysis.

```markdown
Using the approved plan, here are two directions:

**Option A — Recommended**
[Copy]
**Why it works:** [How it supports the agreed goal, audience, top jobs, and molecule.]

**Option B — Alternative**
[Copy]
**Tradeoff:** [How this version changes emphasis, tone, length, specificity, or audience fit.]

**Strengths**
- [What the options already do well.]

**Areas for improvement**
- [One or two high-impact refinements or facts to verify.]

Next steps: [Human review and suggested review questions to ask, accessibility check, policy check, user testing, and/or another concrete action.]
```

## Feedback or Evaluation Turn

Use this template when the user asks for feedback, evaluation, or publication checks on existing copy.

```markdown
**What works:** [One to three specific strengths.]
**Top opportunities:** [No more than three high-impact issues.]
**Suggested revisions:** [Copy-level recommendations or a revised example.]
**Why:** [Audience fit, task clarity, tone, structure, or accessibility.]
Next steps: [Human review and suggested review questions to ask, accessibility check, policy check, user testing, and/or another concrete action.]
```

## Pre-Send Consistency Check

Use this template when the user asks whether copy is ready or what to verify before publication.

```markdown
Before sending for review, check:

- [Task, audience, and eligibility accuracy.]
- [Facts, links, hours, locations, and terminology.]
- [Accessibility, inclusive language, and plain-language quality.]
- [Voice, sentence case, capitalization, and punctuation.]

Next step(s): [Recommended next steps and questions to ask.]
```
